PAINEL PASTORAL V9.3 - CORRECAO DEFINITIVA DO LOGIN ADMIN

CORRECOES DESTA VERSAO
- Mantida a correção PostgreSQL/Neon com psycopg2-binary.
- Na inicialização, o administrador é criado se não existir.
- Se o administrador já existir no Neon, sua senha é sincronizada novamente com INITIAL_ADMIN_PASSWORD.
- O e-mail do administrador é sincronizado por INITIAL_ADMIN_EMAIL.
- Mantidos todos os arquivos diretamente na raiz, sem pastas.

LOGIN ADMINISTRATIVO CONFIGURADO
E-mail: admin@painelpastoral.local
Senha: definida pela variável INITIAL_ADMIN_PASSWORD no Railway.
Para usar a senha combinada: INITIAL_ADMIN_PASSWORD=AdminPastoral2026!

PUBLICAÇÃO NO GITHUB
1. Extraia este ZIP no computador.
2. Abra o repositório painel-pastoral no GitHub.
3. Use Add file > Upload files.
4. Envie os 7 arquivos extraídos diretamente para a raiz do repositório.
5. Substitua os arquivos existentes e confirme o commit na branch main.
6. NÃO envie o ZIP ao GitHub e NÃO crie pastas.

VARIÁVEIS NO RAILWAY
COOKIE_SECURE=1
DATABASE_URL=<connection string completa do Neon>
INITIAL_ADMIN_EMAIL=admin@painelpastoral.local
INITIAL_ADMIN_PASSWORD=AdminPastoral2026!
INITIAL_PASTOR_PASSWORD=123456
SECRET_KEY=<sua chave secreta>

DEPOIS DO COMMIT
1. Aguarde o Railway iniciar um novo deploy.
2. Confirme que o deploy ficou Active/Success.
3. Abra /health no domínio Railway. O esperado é status ok.
4. Abra o painel e entre com admin@painelpastoral.local e a senha configurada em INITIAL_ADMIN_PASSWORD.

OBSERVAÇÃO DE SEGURANÇA
Depois de confirmar o acesso, troque INITIAL_ADMIN_PASSWORD por uma senha exclusiva e forte. No redeploy seguinte, a nova senha será aplicada ao administrador.
